Fixes reproduced cases behind the generic “shared inventory could not be loaded safely” kick:

- Waits and retries temporary database errors and busy handoffs instead of immediately kicking.
- Recovers failed local disconnect saves before reconnect and during periodic saves.
- Allows valid inventories to load when optional XP or tags fail to restore, while preserving those original database fields.
- Adds specific error codes and full underlying console diagnostics. Gameplay inventory input is blocked while a load is waiting.
- Includes a console-only recovery command for legacy login flags, without changing inventory data or releasing token-owned sessions.

**If the kick says `INV-LEGACY`:** confirm that the player is offline on every server, then run `invshare recoverlegacy AFFECTED_NUMERIC_XUID confirm-offline` in the server console. Active token-owned sessions require recovery on their owning server; this command cannot unlock them.

Upgrade all servers sharing the database, preserving their existing plugin data/journals. The shutdown and crash-recovery fixes from v2.7.5 remain included.
