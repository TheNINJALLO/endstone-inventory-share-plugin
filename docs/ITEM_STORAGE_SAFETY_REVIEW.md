# Item-storage safety release qualification

Recorded November 2, 2026 for Endstone 0.11.15 / API 0.11, BDS 1.26.60.6 and protocol 2225. The reported production losses remain unconfirmed without the affected server state. No production database or world was accessed and no production restart was performed.

| Plugin | Release | Change |
| --- | --- | --- |
| InventoryUI | 2.0.10 | Preserve native typed NBT in packets and clones. Checkpoint staged transactions before acknowledgement and roll back rejected changes. Flush menus/cursors before shared inventory capture. |
| Backpacks | 1.0.94 | Preserve NBT, auxiliary data, hidden slots and original lore. Refuse bad reads. Journal failed saves, pause moves, replay recovery and reject callbacks from closed or replaced sessions. |
| Inventory Manager | 1.0.18 | Preserve complete NBT/data and abort unreadable offline inventories before they can be saved as empty. |
| Inventory Share | 2.7.13 | Preserve complete native item data, retire additive bundle restoration and retain ownership while capture or backpack persistence is incomplete. |

The four Python suites passed 140 tests (50 Backpacks, 22 InventoryUI, 3 Inventory Manager and 65 Inventory Share). All 23 isolated MariaDB tests passed. Two disposable BDS runs, one per OS, loaded the four exact candidate wheels together and passed twelve checks each. A real Script API-filled blue bundle contained seven named/lore diamonds and a nested red bundle containing five emeralds. The actual Essentials lore handler added a custom line. The checks covered complete NBT serialization, clones, SQLite, ender chests, MySQL, GUI deposit/close/reopen/withdraw, full-journal rollback, failed-primary freeze/replay and held shared ownership during pending backpack recovery. This used the Essentials handler with a target-selection adapter, not a complete Essentials server deployment.

The final common wheel tuple also passed six physical backpack/block checks and four virtual-vault/cursor checks on Windows, including pagination, item conservation and open-menu shutdown. The Windows Inventory Share wheel passed ten process phases covering restart, forced crash, temporary database errors, handoff, recovery and legacy/optional metadata. The initial phase had auxiliary plugin import errors; later phases loaded them. Separate twelve-check runs establish four-plugin coexistence on both operating systems. The ten-phase process suite was not repeated on Linux.

Seven additional shared-MySQL checks used independent server store/manager instances. The preserved Backpacks 1.0.93 handler reproduced a delayed empty write after one server closed a session, overwriting another server's newer contents. The 1.0.94 closed-session/menu guards prevented that write. This is a reproduced bug matching the reported timing, not proof that it caused the production incident. All participating production servers already share their Backpacks MySQL database.

The release packaging updates README metadata and pins the published InventoryUI wheel URL in Backpacks and Inventory Manager. Every runtime Python file in those three release wheels was compared byte-for-byte with the live-tested candidates. Inventory Share release wheel bytes and its native helpers are unchanged from the live checks. Original qualification hashes are retained in `validation-2.7.13.json`; current downloadable asset hashes and packaging equivalence are recorded in each release's `SHA256SUMS.txt` and `release-provenance.json`.

Stop all participating servers before replacing old writers. Install the common wheels together and choose the Inventory Share wheel for each OS, keeping one version per plugin. The published Backpacks and Inventory Manager dependencies now resolve InventoryUI 2.0.10 directly from its GitHub wheel; the local review's temporary `PIP_FIND_LINKS` setting is unnecessary. Preserve the shared MySQL data, `backpacks.recovery.sqlite3`, `pending-inventories.sqlite3` and original server data. Never clear ownership tokens or delete recovery journals to bypass a failed capture/save. Fully restart after replacement.

Existing lost items or lore need backups or retained database/journal records. Virtual storage still reconciles on the following tick. These checks do not establish universal atomicity across Minecraft world writes and plugin databases, arbitrary power loss, simultaneous cross-server backpack editors, retail controller/touch behavior or arbitrary custom behavior packs. The existing duplicate `manageinv` registration between Backpacks and Inventory Manager remains a separate issue.
