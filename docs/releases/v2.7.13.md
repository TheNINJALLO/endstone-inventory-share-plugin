# Inventory Share 2.7.13

Protect nested bundle contents, custom Essentials lore and cross-server item storage on Endstone 0.11.15 / BDS 1.26.60.6 (protocol 2225).

Native typed NBT is authoritative. Unsupported or unreadable metadata is retained as unresolved data instead of silently becoming a plain item. Additive companion restoration is retired, while historical companion SQL records remain available for manual recovery. The optional companion is read-only diagnostics using stable Script API 2.3.0.

Capture shared inventory after InventoryUI flushes menus and cursors. Hold ownership after failed final capture or while Backpacks has a pending durable save, preventing another server from accepting an older snapshot as current. The qualified 2.7.12 native helpers and exact Endstone/BDS fingerprint guards are unchanged.

Install the matching OS wheel with InventoryUI 2.0.10, Backpacks 1.0.94 and Inventory Manager 1.0.18 when using those integrations. Stop all sharing servers before replacing old writers, retain the existing shared Backpacks MySQL database and both recovery journals, and fully restart. Already missing items require backups or retained recovery records.

Validation: 65 Inventory Share offline tests, 140 tests across the four storage plugins, 23 isolated MariaDB tests, twelve live nested-bundle/lore/fault checks per OS, ten Windows process lifecycle phases and seven shared-database handoff checks. The old Backpacks handler reproduces a delayed empty overwrite; the fixed handler rejects it. This does not establish the cause of the production incident. Retail controls, arbitrary custom packs, simultaneous remote backpack editing and universal power-loss atomicity remain outside these checks.

See [validation](https://github.com/TheNINJALLO/endstone-inventory-share-plugin/blob/v2.7.13/docs/validation-2.7.13.md) and the attached item-storage safety report. No production server or player database was accessed or restarted during verification.
