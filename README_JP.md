# Inventory Share v2.7.7

Endstone サーバー間でインベントリ、防具、オフハンド、エンダーチェスト、経験値などを MySQL/MariaDB に保存・共有するプラグインです。

[English / 詳細な設定手順](README.md) · [リリース](https://github.com/TheNINJALLO/endstone-inventory-share-plugin/releases/tag/v2.7.7)

## ログイン時の切断修正

v2.7.6 は一時的なデータベース障害やサーバー移動時の保存待ちを、既定で15秒間再試行します。経験値やタグの復元だけが失敗した場合は、該当する保存データを保持したままインベントリを復元します。読み込み中はインベントリ操作を制限します。

**v2.7.7 は旧バージョンのロックをログイン時に自動復旧します。** `INV-LEGACY` で切断されていたプレイヤーも、管理者のコマンドや設定変更なしで再接続できます。トークンが NULL または空文字列の古いフラグを、保存済みインベントリを変更せずに新しいセッションへ移行します。同時に接続しても、同じインベントリを取得できるセッションは1つだけです。

既存のセッショントークンがある場合は、ログインフラグが不整合でも保護されます。旧バージョンには所有者や生存確認の情報がないため、必ず同じデータベースを使う全サーバーを停止して一緒に更新してください。詳細は [復旧ガイド](docs/recovery.md) を参照してください。従来のコンソール専用 `invshare recoverlegacy` コマンドは任意の保守用として残りますが、通常の復旧には不要です。

## 再起動時の巻き戻り修正

Bedrock はプラグインの終了処理より先にプレイヤーを削除する場合があります。v2.7.5 は `stop` コマンドの実行前にインベントリを取得し、保存が完了してからログインロックを解除します。通常の退出時と、既定で30秒ごとの定期保存にも対応します。

最新の完全なスナップショットは `pending-inventories.sqlite3` に保持され、次回起動時にログイン受付前に復旧されます。データベースへの保存に失敗した場合、このファイルを削除しないでください。

## 更新方法

1. データベース、ワールド、プラグインのデータをバックアップします。
2. 同じデータベースを使用する全サーバーを停止し、全ての古い wheel を v2.7.7 に置き換えます。旧バージョンとの混在運用はしないでください。
3. 既存の設定とデータを残し、メンテナンス状態で起動してスキーマ更新を確認します。
4. プレイヤーの参加を再開します。トークンのない旧ロックは、対象プレイヤーの次回ログイン時に自動復旧されます。
5. 管理パネルの再起動処理は `stop` を送信し、プロセス終了まで待つよう設定します。

`config.toml` の `autosave_seconds = 30` で定期保存間隔を設定できます（最小5秒）。強制終了や電源断では最後の完全なスナップショット以降の変更を失う場合があります。既に失われたアイテムは、この更新だけでは復元できません。

Endstone API 0.11、Python 3.10以上、InnoDB を使用する MySQL/MariaDB が必要です。実サーバー検証は Windows BDS 1.26.51.1 / Endstone 0.11.11 を使用します。詳細と制限は [検証記録](docs/validation-2.7.7.md) を参照してください。
