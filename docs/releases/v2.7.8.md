Fixes offhand and armor moves being rejected after a shared inventory restore. Inventory Share now applies final slots directly and sends Bedrock's native inventory update, keeping the client's item IDs synchronized. Players do not need to empty their inventory or die.

- Preserves item metadata, unresolved items, automatic legacy recovery, and shutdown/crash protections.
- Adds a small C++ inventory synchronization helper and separate Linux/Windows wheels.
- Requires **BDS 1.26.51.1 x86-64** and **Endstone 0.11.11 or 0.11.12**. Unknown executable builds are blocked before shared inventories are restored. Linux requires glibc 2.35+.

Stop all sharing servers, replace the old wheel with **one wheel matching the server OS** (`linux_x86_64` or `win_amd64`), retain existing data/configuration, then restart and reconnect. CPython 3.10+ uses the same stable-ABI wheel for each OS.

Validation includes 70 automated/database tests, native equipment requests on Linux and Windows, and ten Windows shutdown/recovery phases. These are real BDS tests using an automated protocol client; retail devices and the production multi-plugin stack remain outside the tested scope. See [validation](https://github.com/TheNINJALLO/endstone-inventory-share-plugin/blob/main/docs/validation-2.7.8.md), [recovery](https://github.com/TheNINJALLO/endstone-inventory-share-plugin/blob/main/docs/recovery.md), and the attached artifact reports/checksums.
