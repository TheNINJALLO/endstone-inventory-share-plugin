# Inventory Share 2.7.12

Update the compiled inventory synchronization helper to Endstone 0.11.15 and BDS 1.26.60.6. This resolves the runtime guard failure that rejects every login after moving the server to the runtime required by BlockData 0.6.9. Exact executable fingerprint and SDK version checks remain enabled.

Stop the affected Endstone 0.11.15 / BDS 1.26.60.6 server and replace its 2.7.11 wheel with the 2.7.12 wheel for its OS. Keep the shared database, per-server configuration, and pending-inventory recovery journal. There is no shared schema, serialization, or session-protocol change from 2.7.11. Other servers must keep a plugin version matching their own runtime. Startup finishes native initialization and pending-save recovery before logins are accepted.

The exact Linux and Windows release wheels each passed five live equipment checks and ten shutdown/crash/recovery phases on disposable BDS 1.26.60.6 servers. Clean-stop phases exited successfully; crash phases were intentionally killed and then recovered. CI passed all 79 lifecycle/MariaDB tests on Python 3.11, 3.13, and 3.14, plus both native builds and lint.

The release wheels contain the native libraries from the successful CI build, repackaged with the corrected SDK provenance notice. Those exact repackaged wheel hashes were used for final live qualification and are recorded in the attached evidence. A partial-report read race found in the Windows equipment fixture was fixed with atomic report replacement, then the affected final check passed.

See [validation](https://github.com/TheNINJALLO/endstone-inventory-share-plugin/blob/v2.7.12/docs/validation-2.7.12.md). Server executables, database credentials, and live server data are not included in the release.
